Which bin does this packaging go in?

HKU students and staff face a fixed set of recycling bins, but packaging that is rarely obvious — a milk carton, a coffee cup, a noodle pot. This assistant names the packaging from a product or brand, matches it to a published HKU rule, and answers with the exact bin plus the official source. If it genuinely cannot tell, it asks — then commits to a labelled best guess rather than shrugging.

Who it is for, and what it is not

The problem, the users and the boundary of the system.

  • Users. Anyone sorting on campus who knows the item but not which of the small set of campus bins — or the re Kiosk — takes it.
  • Problem. HKU publishes DO / DON'T guides and photos, but turning "this carton" into the right bin still needs domain knowledge.
  • Not for. Chemicals, e-waste, medical waste and pressurised cans are refused, not sorted. The app does not decide waste policy.

Scope change from the proposal: the daily Smart Recycling Bin stations carry four recycling bins (Paper, Metal, Plastic Bottle, Other Plastic) plus a general-waste bin. Tetra Pak, glass and rechargeable batteries are therefore guided to the re Kiosk, not to a bin that is not there. This replaced an earlier six-way re Kiosk framing.

How it works

Input → processing → output, with a clarifying branch when the packaging is ambiguous.

  1. Input. A product or brand, e.g. "Vitasoy lemon tea".
  2. Identify. The keyword layer — or the AI — names the packaging components.
  3. Match. A deterministic matcher copies a category from data/rules.json.
  4. Answer. Exact bin, instruction and official source URL.

The clarify branch. When the packaging is ambiguous, the app asks one question with fixed options. You answer; it may ask up to two rounds. On the third round it commits to a best_guess — labelled and confidence-capped — instead of refusing. Hazard items and out-of-scope requests bypass this and are refused outright.

Key design rule. The AI identifies; it never decides a category. Categories exist only in data/rules.json, and the matcher is the only component that emits one. If no rule matches, the answer is a refusal — a category is never invented.

What we built vs what the model provides

Domain customisation is the rules, the matcher and the safety layer — not the language model.

Team-built
16 rules, deterministic matcher, clarify state machine, hazard net, dual-channel failover, single-file web UI.
Model / API
Packaging identification, JSON extraction, optional product search. Provider: the course's Alibaba Bailian OpenAI-compatible gateway, model qwen3.8-flash.
Domain customisation
Rules transcribed from HKU's official Recycling 101 poster and photo guide, with the bin actually deployed on campus attached to each item. Every answer carries the rule id, the official source URL and the date the rule was verified.

Try it locally

Standard library only — no build step, no third-party packages. The keyword path works without a key.

git clone https://github.com/Richard-ZJC/AILT9019-gp38
cd AILT9019-gp38
python server.py --mock      # offline demo, no key needed
# open http://localhost:8000

For the live AI path, copy config.example.json to config.json and add the group key; config.json is gitignored. Full setup, API-key options and test commands are in the repository README. On macOS, double-clicking start.command starts the server and opens the browser.

Limitations

Stated against the evidence above.

  • Scope — fixed rule set. Only the 16 published rules are covered. Anything outside them is refused rather than guessed. Covered items must be clean and correctly described.
  • Modality — text-first. Image upload, fuzzy matching and streaming responses are reserved interfaces, not shipped features. Input is normalised for English; Chinese queries are not guaranteed.
  • Location nuance. The official site lists a Glass Bottle slot at two Smart Recycling Bin locations. The app defaults to the re Kiosk, which accepts glass campus-wide — simpler, but not location-aware.
  • Model dependence. The AI path needs the course key and network. Without it the keyword path still answers covered items; everything else degrades visibly rather than guessing.
